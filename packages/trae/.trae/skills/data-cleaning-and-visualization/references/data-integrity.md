# 数据导入与统计预处理

在通用导入器报错，或需要填补、去重、类型转换时阅读。通用脚本只负责保真导入，不替赛题决定数据含义。

## 通用导入器的边界

- 先预检，再运行 `clean_data.py` 或 `run_pipeline.py`；两者支持 `--project-root`。
- 仅消费当前 manifest 批准的原始数据。新爬取的数据也须重新登记、分类和校验哈希。
- CSV/TSV 保留文本编号、空值和重复行；异常字段数直接报错。TXT 只探测逗号、制表符或分号。
- XLSX 每个工作表单独导出，空表记录跳过理由。首行必须是明确且唯一的字段名。
- 公式、合并单元格、多层表头、JSON 嵌套结构需专用读取脚本；不能把诊断 PASS 当成正确解释数据。
- Excel 导出保留单元格值，不保留展示格式。日期、百分比、数值格式显示的前导零及单位仍需核对原表。
- 每次导入使用独立运行目录。下游从当前 `cleaning_report.json.datasets[].cleaned_output` 取路径，不猜测文件名，不递归捡取旧 CSV。
- 清单、原始数据或导出文件变化后，重新导入并更新计划。旧文件保留供排查，不作为本轮结果。

## 赛题代码应明确的事项

在 `data_plan.json` 中按使用到的数据记录工作表、表头位置、字段含义、单位、标识列及空值含义。不必引入额外用户检查点；无法从题面和附件确定且影响结论时才询问。

每项实际变更记录原因、受影响行数或单元格数、变更前后统计及对应代码路径。不得默认认为重复记录是错误，也不能把缺测、零值和不适用混为一类。

预测题先确定时间/分组切分，再在训练集内拟合填补、标准化、编码和特征选择。交叉验证中每个训练折单独拟合；验证集和测试集只应用已拟合变换。不得先对全量数据填均值再划分训练测试集。

清洗报告的 `LOSS_PRESERVING_IMPORT_ONLY` 不是模型正确性或论文质量认证。自定义预处理代码及其输入、输出仍需纳入 S4-S6 的真实运行与证据审计。

## 专用读取脚本的交接

通用导入失败后，专用脚本应真实读取并验证数据，再生成兼容的 `cleaning_report.json`，不能手工把旧报告改成 PASS。报告包含 `schema_version`、UTC `generated_at`、`generated_by`、`status`、`input_hashes`、`datasets`、`skipped_files` 和 `errors`。`input_hashes` 绑定当前 input manifest、使用的原始文件及专用脚本；每个 dataset 至少记录 `path`、`sheet`、`source_sha256`、`cleaned_output`、`output_sha256`、`rows_before`、`rows_after`、`columns`、`transformations` 和 `semantic_validation`。

每个实际修改写入 `transformations`，包含原因和影响范围。复杂源表里的文字说明仍应保留在原附件中并在题意分析中引用；导出值、表头和单位要与原表抽样对照。重新生成数据/图表计划后才能进入建模，不沿用失败前的计划或猜测输出路径。
