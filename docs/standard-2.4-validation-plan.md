# Standard 2.4：实验验证工具升级

## 目标与边界

在现有 S0-S8、数值声明绑定和三端安装包内补充可运行的实验验证工具。
本轮只修改 Standard；不合并其他版本，不发布 Tag/Release，不调用付费模型。
保持当前开发版本号，不修改历史 CUMCM B 题产物。

## 执行顺序

1. `model-code-and-result-generator/scripts/validation_tools.py`：显式时间留出、滚动回测、分组留出；训练内预处理、逐样本预测、基线与样本范围。
2. `scripts/solver_evidence.py`：按需使用 SciPy/HiGHS 解线性/整数规划；记录终止状态、界、差距和求解参数，独立复核声明的约束和目标。
3. `build_result_contracts.py` 与 `paper-formal-writer/scripts/claim_bindings.py`：输出可绑定 CSV 指标和验证报告，拒绝仅用布尔值声明最优。
4. 离线端到端案例与反例测试：输入、实际计算、运行哈希、论文声明；加入 CI。
5. 更新 Skill 按需参考、README、依赖说明，同步 Claude/Codex/Trae 并重建确定性 ZIP。

## 验证方式

- 既有测试全部回归；新增时间倒置、同时间样本分裂、分组泄漏、未来特征、错误维度、求解失败、最优性夸大及产物篡改测试。
- 用可解析的线性预测关系核对回测，用小整数规划穷举核对求解器。
- 使用真实生成的 runner 验证输出与 S7 数值声明契约连接，不手造成功运行记录作为端到端验收。
- 检查三端同步、Skill Creator 校验和 tracked ZIP 的确定性；临时文件放 G 盘。

## 风险与后续

- 划分方式取决于预测目标；按时间、按对象隔离并非可互换，也不能代替特征来源审查。
- 求解器报告不是形式化证明；最优性只针对提交的模型与数值容差，不保证模型忠实于题意。
- 哈希防止运行后误改，不防止有权限的代码伪造整套运行记录。
- 两个合成案例验证程序，不证明真实竞赛论文质量。后续另做授权清晰的真实题盲评。
- 敏感性工具包与完整四类赛题评测集留待下一轮，不给 Lite/Flash 增加重依赖。
