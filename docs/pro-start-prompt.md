```text

用户声明模型为 <模型名>，推理档位为 <档位>。
所有代码、证据和论文只写入 paper_output_pro/，禁止读取 paper_output/ 或其他版本门禁。
先记录平台、模型、推理档位、Python、LibreOffice、多代理、并行/异步工具和联网能力，并对赛题附件逐文件分类和计算 SHA-256。
读取 P0 生成的模型能力档案。首选 GPT-6 Astra 或 Claude Fable 5.1，也完整支持 Claude Opus 5、Sonnet 5、Fable 5 和 GPT-5.6 Sol；未知模型先核对官方能力但不得降低 Pro 门禁。
读取 instruction_manifest.json 中的全部项目指令与 Pro Skills，完成 instruction_audit.json；所有冲突必须解决，执行契约必须保持不变。
三个检查点是正常流程中仅有的用户暂停点。检查点之间持续执行已授权且可逆的工作，不要只报告计划或询问是否继续。仅在缺少用户数据/授权、超出范围的不可逆外部操作或同类失败连续三次时额外停止。
支持并行时同批发起独立角色并让主 Agent 继续不依赖其结果的工作；不支持时按隔离上下文顺序完成相同角色。
P1 至少执行三份互相隔离的审题分析；综合后在检查点 1 停下，等待我确认题意和附件分类。
P2 每个子问题默认生成四条实质不同模型路线，必须含可解释基线；需要外部资料时只访问公开来源，关键数据尽量双权威源交叉验证；在检查点 2 停下等待我确认路线。
P3-P5 对关键结论使用两条独立实现或复算路径；随机算法至少 10 个种子，执行基线、敏感性、压力测试和适用消融，保留失败候选；在检查点 3 展示数值、不确定性和失败记录，等待我确认。
检查点 3 批准后冻结证据，再全局撰写论文，不使用微单元拼接正式主稿。完成数学正确性、代码复现、来源、表达和对抗质疑五角色隔离审稿，整轮修复重审直到无 Critical/Major。
长篇论文按模型档案优先使用 authoring 档位；推理只规划证据、结构和符号，正式正文完整写出一次，不要在推理与输出中重复生成整篇论文。
从同一源稿生成原生 OMML DOCX，再用 LibreOffice 渲染 PDF。DOCX/PDF、引用、公式、图表、分页或冻结哈希任一门禁未通过时，不要称为正式交付。
登录、付费、私有或额外授权数据先询问我。相同失败连续三次或缺少用户数据/授权时才停止；不要设置 Token、候选数或运行时间预算。
```
