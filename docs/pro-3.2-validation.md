# Pro 3.2 本地验收

验证日期：2026-09-05。版本：3.2.0-pro.1。范围仅为独立pro分支。

## 修复的风险

- 复算只信任PASS字符串：改为读取真实运行指标并按预先批准的规则比较。
- 原始附件或新增证据逃过失效检查：重新哈希原文件并校验完整目录清单。
- 无关复算结果被借来证明论文数值：要求数值引用属于该声明的实际复算路径。
- 旧论文审稿结果复用：五角色报告绑定当前主稿、计划和冻结记录。
- 短PDF片段被误判全文一致：双向文本覆盖与正式源稿重建DOCX校验。
- 缺失公式、修改Word样式、图像占位：增加原生公式计数、样式比较和逐页图像检查。
- 重复预检无意义地撤销批准：不变契约保持原哈希；成功重试重置连续失败计数。
- 运行规格事后修改、遗漏失败记录：规格前后哈希、真实回执与完整运行清单。
- 外部关键声明绕过交叉验证、请求意外携带本机凭据：来源声明关联检查，公开检索不继承netrc或认证代理。
- 路径逃逸、旧Pro混装、JSON重复键和非有限数值：统一拒绝并由回归测试覆盖。
- Codex同步错误地改写Python中的多平台检测路径：限定为仅替换Markdown命令路径，
  Python运行代码在两端保持一致；两种ZIP都必须解压后实际预检并验证跨平台混装检测。

## 本地验证

Windows / Python 3.11.1：54项回归测试通过，包含真实求解和LibreOffice渲染集成。
两端共20个SKILL入口通过Skill Creator校验；最长入口139行。Python编译、依赖
`pip check`、两端同步、安装包逐字节校验与两次构建一致性通过。

ZIP固定时间、权限、创建平台及文件顺序，文本统一LF；使用stored条目避免不同
zlib版本影响归档哈希。CI在构建前直接校验仓库已有ZIP，防止“先重建后验证”掩盖
陈旧安装包。远端六组合CI的完成状态以对应提交的GitHub Actions结果为准。

## 不能宣称的结论

开发样例明确模拟P1读者和三个用户决定，**没有**据此声称完成真人审批的竞赛流程。
五个论文审稿上下文与数值复现是真实执行的，但宿主返回的代理记录不暴露精确
底层模型ID；本次不作为Astra或Fable的模型资格认证。尚未完成四类真实赛题的
双模型前向测试，也不能保证论文获奖。

哈希和回执能发现陈旧或不一致的材料，不能防止同一权限主体主动重写全部证据。
运行器不是安全沙箱；来源快照不自动证明权威性，角色数也不自动证明意见独立。
是否建模恰当、假设真实、论证有价值，仍需要实际审阅和真实任务评估。
